# Product Value

## このサービスが提供する価値

Project Polaris は、単なるログ閲覧ツールではありません。

**アクセスログを整理し、「今どこを見るべきか」「どの程度急いで確認すべきか」「次に何を確認すればよいか」を判断しやすくする実務支援ツール**です。

Analyzerは大量ログを集計・圧縮し、AIはその観測結果の意味・可能性・確認事項を説明します。

---

## 解決したい課題

### ログを見ること自体が負担

制作や運用が本業であり、ログ調査はイレギュラー対応です。

調査のために本来の制作業務が止まってしまいます。

### 判断に自信が持てない

404、5xx、特定Pathへのアクセス、Botらしいアクセスなどを見つけても、

- 今すぐ見るべきか
- 後回しでよいか
- どこまでログから確認できるか
- 次にどのログや設定を見るべきか

を短時間で判断するのは簡単ではありません。

### 実務へつなげにくい

ログ調査のあとには、

- 修正
- 報告
- 提案
- 保守

という仕事が続きます。

Project Polaris は、一次切り分けで終わらず、その後の実務へつながる材料を整理します。

---

# 無料利用で提供したい価値

目的は**トラブル対応を早く終わらせること**です。

最低限、ユーザーが次を確認できる状態を目指します。

- Analyzerによる基本集計
- Path / IP / Status / Method / User-Agent / 時間帯などのObservation
- Parse Warning
- TruncationなどのData Limitation
- Known Information
- 解析対象・除外条件の確認

AI Summary、Overall Urgency、Next Checkなど、AI実行を伴う機能を無料範囲にどこまで含めるかは、AIコストとProduct Planを踏まえて別途決定します。

無料・有料の違いによってAnalyzerの解析精度そのものは変えません。

---

# 有料利用で提供したい価値

目的は**解析結果を継続的な保守・改善の仕事へ変えること**です。

候補となる提供価値は以下です。

- AIによる詳細Explanation
- AIチャット
- Next Checkの深掘り
- 解析履歴
- 前回比較・改善前後比較
- サイト単位管理
- PDF / Markdownレポート生成
- クライアント向け説明
- 保守・改善提案のたたき台
- レポート共有

具体的なEntitlementはProduct Planで確定します。

---

# このプロダクトで重視すること

## Analyzerの観測事実を隠さない

AIを利用できない場合でも、Analyzerの集計結果を確認できる構造にします。

## 解析品質情報を隠さない

以下はプランに関係なく確認可能にします。

- Parse失敗
- Partial Parse
- Truncation
- Exclusion
- Redaction
- 利用できなかったAggregation View

## 数値Scoreを目的にしない

Health Scoreは初期実装では採用しません。

代わりに、AIを利用する場合は、

```text
Low
Normal
High
Immediate
```

の`Overall Urgency`によって、

**この解析結果をどの程度早く人が確認した方がよいか**

を説明できる構造とします。

Overall UrgencyはRisk Scoreや攻撃確率ではありません。

# 成功の定義

無料利用：

> 困ったら、まずPolarisでログを整理しよう。

有料利用：

> インシデント対応のあとも、履歴・比較・報告・提案・保守に使おう。
